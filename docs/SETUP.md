# Owner setup steps

Everything Skyfly needs that only the owner can do. You never need to paste
passwords or keys into chat. Enter them directly in GitHub, Render or Supabase.

## 1. Let Claude push to the `skyfly` repository

The Claude GitHub App must have access to `roseskincare9-code/skyfly`:
https://github.com/apps/claude/installations/select_target → choose the account →
add `skyfly` to the selected repositories. Optionally, make the repository private
under GitHub → skyfly → Settings → General → Danger Zone → Change visibility.

## 2. Choose the database

Skyfly needs one PostgreSQL database of its own. Either option works without code changes:

| | Render Postgres (recommended) | Supabase Postgres |
|---|---|---|
| Cost | Paid plan for a persistent database (free databases expire) | Free tier available |
| Caveats | Same provider as the app, simplest setup | Free projects pause after a period of inactivity, and orders fail while paused |
| Settings | `DATABASE_URL` from Render, `DATABASE_SSL=false` | Session pooler connection string, `DATABASE_SSL=true` |

**Why not Supabase Auth?** Skyfly has one owner login on a server-rendered
dashboard. Password login with server-side sessions (hashed passwords,
httpOnly secure cookies, CSRF tokens, rate limits) is already built in and
tested. Supabase Auth would add a browser SDK, token handling and a second
system to configure, without adding protection for this use. If you choose
Supabase, use it for the database only.

## 3. Choose the addresses (one domain needed for page hosting)

Skyfly needs **two different hostnames**:

| Setting | What it is | Example |
|---|---|---|
| `PUBLIC_BASE_URL` | the dashboard and order API | `https://skyfly.onrender.com` (free Render address) |
| `PAGES_BASE_URL` | where hosted landing pages live | `https://pages.yourbrand.com` |

They must differ because a hosted page's scripts must never be able to read your
dashboard. Render gives each service only one free `onrender.com` address, so
**hosting pages needs one domain you own** (bought from any registrar), or a
subdomain of one you already have. Add the pages subdomain to the Skyfly service
in Render (Settings → Custom Domains). Each page can also get its own custom
domain later.

Without `PAGES_BASE_URL`, everything else still works: orders, dashboard, pixels
via the script tag on pages hosted elsewhere (e.g. GitHub Pages). Only page
hosting is switched off.

## 4. Deploy on Render (needs your approval, since it costs money)

1. Render dashboard → **New → Blueprint** → connect the `skyfly` repository (not AIVORA). Render reads `render.yaml`.
2. Review the plans shown (web service `starter`, database `basic-256mb`) and the region.
   - For Supabase: delete the `databases:` section and the `fromDatabase` link first, then set `DATABASE_URL` and `DATABASE_SSL=true` by hand.
3. Set `PUBLIC_BASE_URL` to the service URL Render shows, e.g. `https://skyfly.onrender.com` (or `-xxxx.onrender.com`), and `PAGES_BASE_URL` (step 3 above).
   `SESSION_SECRET` and `SKYFLY_ENCRYPTION_KEY` are generated by Render. If Render's generated key is not 32 bytes, Skyfly
   refuses to start with a clear message; then set it yourself in Render to the output of
   `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` (run on your own computer, never paste it in chat).
4. Deploy. Migrations run automatically before each deploy (`npm run migrate`).
5. Open `https://<skyfly-url>/healthz`. It must show `{"status":"ok"}`.

## 5. Create your owner account and the Larose business

1. Open `https://<skyfly-url>/signup` and create your account (password of at least 10 characters).
2. In Render → skyfly → **Shell**, run:
   `npm run seed:larose -- your-email@example.com`
   This creates *Larose Natural Skincare Nigeria* with the 5 packages and prices from the live page, the WhatsApp number 09049206695, and the registered landing page (form key `larosenigeria`).
3. In Render → skyfly → **Environment**, set `ALLOW_SIGNUP=false` so nobody else can sign up.
4. Log in and check **Products** (prices) and **Settings** (WhatsApp number).

## 6. Connect the landing page

Either keep it on GitHub Pages and follow `integrations/larosenigeria/README.md`,
or import it into Skyfly (see docs/GUIDE.md). Then place one real test order on
the live page, confirm it appears in **Orders**, and mark it Cancelled.

## 7. Pixels (optional)

See docs/GUIDE.md section 3. Access tokens are entered only in Skyfly's Pixels
screen, never in chat.

## Environment variables

| Name | Required | Example / notes |
|---|---|---|
| `NODE_ENV` | yes | `production` |
| `DATABASE_URL` | yes | Skyfly's own Postgres connection string |
| `DATABASE_SSL` | no | `true` for Supabase or external URLs; defaults to `true` in production |
| `SESSION_SECRET` | yes | 32+ random characters (Render generates it) |
| `PUBLIC_BASE_URL` | yes (prod) | `https://skyfly.onrender.com` |
| `PAGES_BASE_URL` | for hosting | `https://pages.yourbrand.com`, on a different host from `PUBLIC_BASE_URL` |
| `SKYFLY_ENCRYPTION_KEY` | for server Purchase | 32 random bytes, base64. Keep stable |
| `ALLOWED_ORIGINS` | no | extra websites allowed to submit orders; each page's own URL is allowed automatically |
| `META_GRAPH_BASE` / `TIKTOK_API_BASE` / `TIKTOK_PURCHASE_EVENT` | no | override ad-platform API versions/names if the platforms change them |
| `ALLOW_SIGNUP` | no | `true` only while creating the owner account |
| `ORDER_RATE_LIMIT` | no | submissions per IP per 10 minutes, default 20 |
| `PORT` | no | set by Render |

## Backups

Render's paid Postgres plans include automatic daily backups; check the
database's **Recovery** tab after creating it. Hosted landing-page files are stored in the
same database, so they are included in those backups. You can also download all orders at
any time with **Orders → Export CSV**.
